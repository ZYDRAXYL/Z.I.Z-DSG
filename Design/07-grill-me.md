# 07 — Grill-me: คำถามที่เจ้าของต้องตัดสิน (Z.I.Z)

> 29 คำถาม เรียงเป็นรอบตามต้นไม้การตัดสินใจ · รอบ 1 = ไม่มีอะไรต้องตัดสินก่อน · ในแต่ละรอบเรียงจากผลกระทบมากไปน้อย
> คำถามระดับ Eco (repo สัญญา, `.zeco`, รูปแบบเวอร์ชัน ฯลฯ) อยู่ที่ `Zydraxyl-HUB/Design/eco/GRILL-ME.md` — ที่นี่ถามเฉพาะเรื่องของ Z.I.Z

## รอบ 1 — รากของต้นไม้

❓ **Q1** - **Z.I.Z ต้องใช้งานได้เมื่อไม่มี CLI agent หรือไม่**: เจ้าของบอกว่า Z.I.Z ใช้ agent ของผู้ใช้ แต่ก็บอกว่า "ต่อยอดระบบ Analysis เดิม" (Sage ของ DraconDex ไม่ใช้ AI เลย) และ "อ่าน Excel แล้วแปลงเป็นข้อมูลแอป" (ทำได้ด้วยการจับคู่คอลัมน์) — (ก) **บังคับมี agent**: ไม่มี = หน้าแนะนำการติดตั้งเท่านั้น โค้ดน้อยกว่า แต่คนที่ไม่ใช้ AI ใช้ Z.I.Z ไม่ได้เลย · (ข) **โหมดไม่มี AI**: Insight + นำเข้าตาราง + แบ่งต้นฉบับ + ตรวจ/นำไปใช้/ย้อน ใช้ได้ ส่วน AI จาง · (ค) แยกเป็นสองแอป

➡️ (ข) — Insight และการนำเข้าแบบ deterministic คือสิ่งที่ Sage เดิมทำอยู่แล้ว และทำให้ Z.I.Z มีประโยชน์ตั้งแต่วันแรกโดยไม่ผูกกับบริษัท AI ใด (`02-architecture.md` §3.4)

✅ **ตัดสินแล้ว 2026-11-01:** มีโหมดไม่มี agent

---

❓ **Q2** - **agent ที่ "รองรับอย่างเป็นทางการ" ใน v1**: แต่ละตัวมีความเสี่ยงต่างกัน — Claude Code ต้องผ่าน adapter ACP ของบุคคลที่สาม · Codex ผ่าน `codex-acp` และโหมด headless ใช้ MCP ไม่ได้ (รายงาน) · Gemini CLI มี ACP ในตัวแต่หยุดให้บริการผู้ใช้ฟรี/AI Pro ตั้งแต่ 2026-06-18 · ทางเลือก: (ก) Claude Code อย่างเดียว · (ข) **Claude Code + Codex เป็นทางการ, Gemini + "คำสั่ง ACP กำหนดเอง" เป็นแบบพยายาม** · (ค) ทุกตัวเท่ากัน — ยิ่งรับรองมาก ยิ่งต้องทดสอบทุกครั้งที่ CLI อัปเดต

➡️ (ข) — ครอบคลุมผู้ใช้ส่วนใหญ่ และช่อง "ACP กำหนดเอง" เปิดทางให้ Goose/Ollama โดยไม่ต้องรับรอง

✅ **ตัดสินแล้ว 2026-11-01:** Claude Code + Codex ทางการ · Gemini และ ACP กำหนดเอง แบบพยายาม

---

❓ **Q3** - **agent เห็นอะไร: gateway หรือต่อแอปตรง**: (ก) **gateway** — agent เห็นแค่ MCP `zydraxyl-ziz` ที่ Z.I.Z คุม; Z.I.Z เป็น client คนเดียวของแอป; agent **ไม่มีทาง**เรียก `eco_apply`/`eco_delete` · (ข) **ตรง** — ส่ง MCP ของแต่ละแอปให้ agent, agent เรียก `eco_propose`/`eco_apply` เอง, ป้องกันด้วยสิทธิ์ในแอป (ECO-S1) อย่างเดียว; โค้ด Z.I.Z น้อยกว่าแต่ prompt injection ไปถึงปุ่มเขียนได้ · (ค) ผสม: อ่านตรง เขียนผ่าน Z.I.Z

➡️ (ก) — การป้องกันที่แข็งที่สุดคือ "ไม่มีเครื่องมือให้ใช้" ไม่ใช่ "ถามก่อนใช้" (`04-internals.md` §7.1 ชั้น 1)

✅ **ตัดสินแล้ว 2026-11-01:** **ผสม: อ่านตรง เขียนผ่าน Z.I.Z** (ต่างจากที่แนะนำ) → `02` §4.3 · แอปต้องมีโหมด `--read-only` (P17) · ❓ Q47

---

❓ **Q4** - **ใครอนุมัติการเขียน: Z.I.Z, แอป, หรือทั้งคู่**: สัญญา ECO-S2 ให้แอปเป็นผู้ยืนยัน ส่วน Z.I.Z มีหน้าตรวจข้อเสนอละเอียดอยู่แล้ว ถ้ายืนยันทั้งสองที่ = ผู้ใช้กดสองครั้งต่อชุด · (ก) **Z.I.Z ตรวจรายละเอียด + แอปยืนยันสรุปหนึ่งครั้งต่องาน (batch grant ผูก job)** · (ข) แอปแสดง diff เต็มทุกครั้ง (ซ้ำกับ Z.I.Z) · (ค) เชื่อ Z.I.Z ทั้งหมด แอปไม่ถาม — ขัด ECO §14 "ผู้ตัดสินคือแอปเจ้าของข้อมูล"

➡️ (ก) — แอปยังเป็นผู้ตัดสินตามสัญญา แต่ผู้ใช้ไม่ต้องตรวจซ้ำสองที่ (ข้อเสนอ P5)

---

❓ **Q5** - **"ย้อนการเขียนของ AI" ต้องรับประกันระดับไหน**: (ก) **ย้อนทั้งชุดจาก snapshot** — ง่าย แต่ลบงานที่ผู้ใช้แก้หลังจากนั้นด้วย · (ข) **ย้อนรายรายการ (inverse op)** + ถ้ารายการถูกแก้หลัง apply ให้แอปรายงาน conflict แล้วเสนอย้อนเฉพาะที่ไม่ถูกแก้ — ทุกแอปต้องทำ `eco_revert` (ข้อเสนอ P3) · (ค) Z.I.Z ไม่ย้อนเลย ส่งผู้ใช้ไปปุ่มในแอป (ECO-S3 ขั้นต่ำ)

➡️ (ข) — ผู้ใช้ไม่ควรเสียงานตัวเองเพื่อย้อนงาน AI; ค่าใช้จ่ายตกที่แอปละหนึ่ง tool ซึ่งเป็นสัญญากลางที่ทดสอบด้วยแอปปลอมได้ (P9)

---

❓ **Q6** - **ข้อมูลของ Z.I.Z (สำเนานิยาย, ผลวิเคราะห์, log) เก็บที่ไหน**: (ก) **ในโฟลเดอร์โปรเจกต์ Eco** `<EcoProject>\ZIZ\` — ย้าย/สำรองไปพร้อมโปรเจกต์ แต่โฟลเดอร์ที่ sync ขึ้น cloud (OneDrive) จะพาสำเนานิยายไปด้วย · (ข) **`%LOCALAPPDATA%\ZIZ\`** เท่านั้น — เป็นส่วนตัว แต่ย้ายเครื่องแล้วหาย · (ค) ให้ผู้ใช้เลือกตอนสร้าง

➡️ (ก) โดยโฟลเดอร์ธรรมดาที่ไม่ใช่โปรเจกต์ Eco ไปที่ (ข) — ตรงกับ "เปิดโฟลเดอร์โปรเจกต์ใน Z.I.Z" และเป็น `members.ziz` ตาม ECO-L7

---

❓ **Q7** - **นิยายของผู้ใช้ถูกส่งให้บริษัท AI — ค่าเริ่มต้นคืออะไร**: agent ของผู้ใช้ส่งข้อความไปผู้ให้บริการโมเดลเสมอ (Z.I.Z ห้ามไม่ได้) · (ก) **opt-in ต่อโปรเจกต์ + แจ้งครั้งแรก** (ECO-S5) · (ข) แบบ (ก) + ธง "เฉพาะ agent ที่ผู้ใช้ประกาศว่าทำงานในเครื่อง" (Z.I.Z ตรวจไม่ได้จริง เชื่อคำประกาศ) · (ค) ไม่ถามเลย (ผู้ใช้เลือก agent เองแล้ว)

➡️ (ข) — ธงช่วยคนที่มีต้นฉบับลับ โดยบอกตรง ๆ ว่าเป็นคำประกาศของผู้ใช้ ไม่ใช่การตรวจของ Z.I.Z

---

❓ **Q8** - **Z.I.Z ห้ามมีโมเดล/API key ของตัวเองตลอดไปหรือไม่**: (ก) **ห้ามตลอด** — Z.I.Z ไม่ถือความลับ ไม่ต้องดูแลราคา/โควตา ผู้ใช้ที่อยากใช้โมเดลในเครื่องไปทาง agent ที่ต่อ Ollama ได้ · (ข) ห้ามใน v1 พิจารณาภายหลัง · (ค) มีช่องใส่ API key เป็นทางเลือก

➡️ (ข) — ยึดหลักของเจ้าของใน v1 แต่ไม่ปิดประตูถาวรจนกว่าจะเห็นว่าผู้ใช้ติดตั้ง CLI ไม่ไหวจริงหรือไม่

✅ **ตัดสินแล้ว 2026-11-01 (เจ้าของ):** มี**โมเดลเล็กในเครื่อง**ได้ เพื่อแบ่งภาระจาก CLI agent — ยังไม่มี API key / cloud / LLM ใหญ่ · งานตัดสินและเขียนยังเป็นของ agent → `08-local-models.md`

---

❓ **Q9** - **อ่านไฟล์ native ของแอปเมื่อไม่มี MCP ได้ไหม**: เช่น DraconDex มีโฟลเดอร์ Locate ที่เก็บ `.ddata`/`.dpage` เป็น JSON (`V5.md` §8.5) — อ่านได้ทันทีโดยไม่ต้องเปิดแอป · (ก) **ไม่ได้** — อ่านผ่าน MCP หรือ `.zeco` ที่ส่งออกเท่านั้น (หลักการข้อ 3 ของสัญญา, รูปแบบ native เปลี่ยนเมื่อไรก็ได้) · (ข) อ่านได้แบบอ่านอย่างเดียวเฉพาะรูปแบบที่แอปเจ้าของประกาศว่าเป็นสาธารณะ · (ค) อ่านได้ทุกอย่าง

➡️ (ก) — ไม่งั้น Z.I.Z จะพังทุกครั้งที่แอปเปลี่ยนรูปไฟล์ภายใน; Insight ใช้ `.zeco` ล่าสุดแทนเมื่อแอปปิด

---

❓ **Q10** - **Z.I.Z ลบข้อมูลในแอปได้ไหม**: (ก) **ไม่ได้ใน v1** — recipe มีแค่ create/update/link; "ลบ" ผู้ใช้ทำในแอปเอง · (ข) ได้ ผ่าน `eco_delete` ยืนยันทุกครั้ง (ECO-S2) · (ค) ได้เฉพาะสิ่งที่ Z.I.Z สร้างเองในงานเดียวกัน (= การย้อน, ซึ่งเป็น Q5 อยู่แล้ว)

➡️ (ก) — คำสั่งลบคือเป้าหมายอันดับหนึ่งของ prompt injection และไม่มี recipe ไหนที่ต้องลบจริง

---

❓ **Q11** - **Z.I.Z ทำงานเบื้องหลังได้แค่ไหน**: (ก) เปิดแอป Eco ที่ปิดอยู่ให้เองเมื่อต้องอ่าน/เขียน (shim ของแอปทำได้ตาม ECO-C5) · (ข) ต้องให้ผู้ใช้เปิดแอปเองก่อน · และ (ค) ตั้งเวลารันงานเอง (เช่นทุกคืนทำงานค้างของ Ourobask) หรือไม่

➡️ (ก) แต่ **ไม่มีการตั้งเวลาใน v1** — การเปิดแอปให้เป็นแค่ความสะดวก; การรันเองตอนผู้ใช้ไม่อยู่ทำให้เกิดค่าใช้จ่าย AI ที่ผู้ใช้ไม่เห็น

---

❓ **Q12** - **โครง repo ของ Z.I.Z**: (ก) **repo เดียว `Z.I.Z-DSG`** (เปลี่ยนชื่อเป็น `Z.I.Z` หรือ `ZIZ-APP` ตอนเริ่มโค้ด?) · (ข) chain แบบ DraconDex (APP hub + EXE + WEB mirror) — สัญญา ECO-G2 ยังเปิดคำถามนี้ · และ public หรือ private (ถ้า private ต้องมี repo mirror สำหรับ release ตาม ECO-K4, และการยกโค้ดจาก DraconDex-EXE ที่ private เข้า repo public คือการเปิดเผยโค้ดส่วนนั้น)

## รอบ 2 — ขึ้นกับคำตอบรอบ 1

❓ **Q13** - **bundle adapter ACP ไว้ในตัวติดตั้งหรือไม่** (ขึ้นกับ Q2): Claude Code ต่อผ่าน ACP ได้ด้วย adapter (npm, TypeScript) · (ก) **bundle เวอร์ชันที่ pin + ตรวจ licence** และรันด้วย Node ของ Electron — ผู้ใช้ไม่ต้องมี Node; Z.I.Z ต้องออก release ทุกครั้งที่ adapter ต้องอัปเดตเพราะ CLI เปลี่ยน · (ข) ให้ผู้ใช้ติดตั้ง adapter เอง (`npx`) — ยืดหยุ่นแต่ยากสำหรับผู้ใช้ทั่วไป · (ค) ดาวน์โหลดตอนใช้ครั้งแรกพร้อม sha256 pin

➡️ (ก) และมีช่อง "ใช้ adapter ของฉันเอง" สำหรับผู้ใช้ขั้นสูง — ลดขั้นตอนติดตั้งเหลือแค่ CLI ที่ผู้ใช้มีอยู่แล้ว

---

❓ **Q14** - **Codex โหมด headless ใช้ tool ไม่ได้ — ยอมโหมด prompt-only ไหม** (ขึ้นกับ Q2): prompt-only = Z.I.Z ใส่ chunk ลง prompt แล้วขอ JSON กลับ ใช้ได้กับทุก CLI แต่ agent มองไม่เห็นข้อมูลเดิมในแอป (จับคู่ชื่อซ้ำแย่ลง) และใช้ token มากกว่า · (ก) **ยอม เป็นทางสำรองเมื่อ ACP ใช้ไม่ได้** · (ข) Codex ต้องผ่าน ACP เท่านั้น · (ค) ไม่รองรับ Codex

➡️ (ก) — Z.I.Z ทำการจับคู่กับข้อมูลเดิมเองอยู่แล้วในขั้น matching (`04-internals.md` §4) จึงเสียไม่มาก

---

❓ **Q15** - **ให้ Z.I.Z ลงทะเบียน MCP ของแอป Eco เข้า agent ของผู้ใช้ (ใช้ใน terminal นอก Z.I.Z) ไหม** (ขึ้นกับ Q3): เจ้าของอยาก "ทำให้แอป Eco เข้าถึงง่ายขึ้น" — ปุ่ม "ใช้แอป Eco ใน Claude Code" เขียน `.mcp.json`/`config.toml`/`settings.json` ให้ · แต่นอก Z.I.Z ไม่มี gateway → การป้องกันเหลือแค่สิทธิ์ในแอป (ECO-S1) · (ก) **มี เป็น opt-in ต่อแอป ห้าม `trust:true`** · (ข) ไม่มี (ผู้ใช้ตั้งเอง) · (ค) ให้ Hub ทำแทน

➡️ (ก) — สัญญา §9.4 อนุญาตไว้แล้ว และสิทธิ์ในแอปยังเป็นผู้ตัดสิน; บอกผู้ใช้ตรง ๆ ว่าเส้นทางนี้ไม่มีหน้าตรวจข้อเสนอของ Z.I.Z

❓ **Q16** - **batch grant ของงานหนึ่งกว้างแค่ไหน** (ขึ้นกับ Q4): (ก) **ต่อ job: ครั้งเดียวต่องาน ≤ จำนวน entity ที่แสดงตอนขอ หมดอายุเมื่องานจบหรือ 24 ชม.** · (ข) ต่อ session ของแอป (จนปิดแอป) · (ค) ต่อโปรเจกต์ N วัน — สะดวกที่สุด เสี่ยงที่สุด
