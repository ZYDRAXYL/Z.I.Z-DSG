| วง 2 | กลุ่ม entity ต่อแอป (ตัวละคร/สถานที่/บท/หน้า/งาน…) · แหล่งที่นำเข้า · job | ขนาดตามจำนวน |
| ดาวเทียม | **✦ คำแนะนำ** · **⚠ ปัญหา** (ลิงก์เสีย/ชื่อซ้ำ) | เรืองแสงอ่อน · คลิก = เปิดในแผงขวา |
| เส้น | ลิงก์ข้ามแอป (ความหนา = จำนวน) · `┄` ลิงก์เสีย · **ชีพจร** วิ่งตามเส้นเมื่อ agent/โมเดลอ่านข้อมูลแอปนั้นผ่าน gateway | — |

- **ดับเบิลคลิกกลุ่ม** = ขยายเป็น entity (สูงสุด 150 โหนดบนหน้าจอ · เกิน → "แสดง 150 จาก 214 · กรอง") · กราฟเต็มอยู่ที่ Insight (≤ 2,000)
- **ลากโหนดเข้าแชต** หรือพิมพ์ `@อาริน` = แนบ ref ให้ agent (`zydraxyl://` ref) · คลิกขวา = เปิดในแอปเจ้าของ (ECO-C3) / เปิดใน Mirror / ค้นในต้นฉบับ (`09` §5)
- เส้นชีพจรมาจาก event จริง (`tool_call` ใน `runs/*.ndjson`) — "บอกเสมอว่าใครทำ" (หลักข้อ 6) แบบมองเห็นได้
- แผงขวา = รายละเอียดโหนดที่เลือก: สถิติ · คำแนะนำของโหนด · ปุ่มหลักหนึ่งปุ่ม

### 2.3 2D / 3D

| | 2D (ค่าเริ่ม) | 3D (เลือกได้) |
|---|---|---|
| วาด | Canvas 2D + force layout (d3-force, ISC) | WebGL — three.js (MIT) โหลด**เมื่อสลับครั้งแรกเท่านั้น** |
| ใช้เมื่อ | ทุกเครื่อง · ทำงานจริง | ชมภาพรวมโปรเจกต์ใหญ่ · หมุน/ซูมด้วยเมาส์ |
| ตกกลับ | — | WebGL ไม่มี / GPU ถูก blocklist → ปุ่ม 3D ปิดพร้อมเหตุผล |

- ตำแหน่งโหนดคงที่ต่อโปรเจกต์ (seed จาก id + บันทึกตำแหน่งที่ผู้ใช้ลาก) → แผนที่ไม่ "กระโดด" ทุกครั้งที่เปิด (กฎ Kensaku: ห้ามสลับลำดับใต้มือผู้ใช้)
- layout คำนวณใน worker · หยุด simulation เมื่อนิ่ง (ไม่กิน CPU ตอนว่าง)
- **`prefers-reduced-motion`** → ไม่มีชีพจร/ลอย · ใช้ไอคอนสถานะแทน

### 2.4 Accessibility ของกราฟ

- **มุมมองรายการ ☰** (ปุ่มบนแถบสถานะ, `Alt+L`) = ข้อมูลเดียวกันเป็น tree list ที่ใช้คีย์บอร์ด/screen reader ได้ — เป็นทางเลือกที่เท่าเทียม ไม่ใช่ของแถม
- คีย์บอร์ดบนกราฟ: `Tab` วนโหนดตามวง · ลูกศร = เลื่อนไปโหนดเพื่อนบ้าน · `Enter` = เลือก · `Space` = ขยาย/ยุบ
- canvas มี `role="application"` + live region ประกาศโหนดที่ focus ("BahaMyth · entity 214 · เชื่อมแล้ว · คำแนะนำ 3")
- สีแอปทุกสีมีป้ายตัวอักษร/ไอคอนคู่เสมอ

## 3. AI Mirror Workstation

### 3.1 แนวคิด

ผู้ใช้ไม่มั่นใจว่าจะแก้อะไร หรืออยากให้ AI ลองแก้ก่อนแต่ไม่อยากเสี่ยง → เปิด **🪞 Mirror** →
หน้าจอแยกเป็น **Duo view**:

- **ซ้าย = ต้นฉบับ** — snapshot ตอนเปิด Mirror · **อ่านอย่างเดียว ไม่เปลี่ยนเลย**
- **ขวา = กระจก** — สำเนาที่ AI แก้ (agent + โมเดลเล็ก) · ทุกจุดที่เปลี่ยนเป็น **ก้อนการเปลี่ยน (hunk)** มีหมายเลข
- ผู้ใช้ติ๊กเลือกก้อนที่ต้องการ → **"นำ N ก้อนไปใช้"** → กลายเป็น changeset เดิมของ Z.I.Z (`04` §6) → `eco_propose` → `eco_apply` → แอปทำ snapshot/ย้อนได้ (ECO-S3)

Mirror **ไม่ใช่ระบบเขียนใหม่** — เป็น UI อีกแบบของ changeset ที่ละเอียดถึงระดับก้อน · กฎเดิมทั้งหมดใช้ต่อ: ปุ่มเขียนมีที่เดียว · ย้อนได้ · ไม่มีอะไรเขียนจนกด

### 3.2 Layout

```
┌──────────────────────────────────────────────────────────────────────────────────────────────┐
│ 🪞 Mirror · RyuLong › Moonfall › บทที่ 3        สั่ง AI: [ทำให้บทสนทนากระชับขึ้น…      ] [ให้ AI แก้] │
├───────────────────────────────────────┬──┬───────────────────────────────────────┬───────────┤
│ ต้นฉบับ (ไม่เปลี่ยน) 🔒                 │  │ กระจก (AI แก้) · Claude Code + ner 1.3 │ การเปลี่ยน 7│
│                                       │①│                                       │ ☑ ① กระชับ │
│ อารินเดินเข้ามาในห้องอย่างช้า ๆ แล้วเขา  │━━│ อารินก้าวเข้าห้องช้า ๆ                  │   บทสนทนา  │
│ ก็ค่อย ๆ นั่งลงบนเก้าอี้ไม้ตัวเก่า        │  │ แล้วทรุดลงบนเก้าอี้ไม้ตัวเก่า            │ ☑ ② ชื่อ   │
│                                       │②│                                       │   "ริน"→   │
│ "ริน เจ้ามาทำอะไรที่นี่"                 │━━│ "อาริน เจ้ามาทำอะไรที่นี่"              │   "อาริน"  │
│                                       │  │                                       │ ☐ ③ ตัด    │
│ ...                                   │③│ ...                                   │   ย่อหน้า   │
│                                       │  │                                       │ ⚠ ④ ล้าสมัย│
│                                       │  │                                       │ ...        │
├───────────────────────────────────────┴──┴───────────────────────────────────────┴───────────┤
│ เลื่อนพร้อมกัน ⇅ · ‹ทีละประโยค | ทีละคำ› · ◀ ก้อนก่อน  ก้อนถัดไป ▶     [ยกเลิก] [นำ 2 ก้อนไปใช้] │
│ RyuLong จะถามยืนยัน 1 ครั้ง และเก็บจุดย้อนให้อัตโนมัติ                                              │

```

- **รางกลาง** = หมายเลขก้อนเชื่อมสองฝั่ง (เส้นโค้งจากตำแหน่งซ้ายไปขวา) · คลิกหมายเลข = กระโดดทั้งสองฝั่ง
- **เลื่อนพร้อมกัน** เป็นค่าเริ่ม (ปิดได้) · ความยาวต่างกันจัดตำแหน่งด้วย anchor ของก้อน
- แต่ละก้อน: `☑ ใช้` · `☐ ไม่ใช้` · `✎ แก้เอง` (แก้ในฝั่งขวาเฉพาะก้อนนั้น) · `↻ ให้ AI ลองใหม่เฉพาะก้อนนี้` · เหตุผลสั้นที่ AI ให้ + หลักฐาน (หลักข้อ 3)
- **⚠ ล้าสมัย:** ต้นฉบับในแอปเปลี่ยนหลังเปิด Mirror (ตรวจ `version`/etag ผ่าน `eco_get`) → ก้อนที่ทับส่วนที่เปลี่ยนถูกปิดเลือก + ปุ่ม "สร้างกระจกใหม่จากฉบับล่าสุด"
- สั่งซ้ำได้หลายรอบ: แต่ละรอบเป็น "รุ่นกระจก" (r1, r2…) ย้อนดูได้ · ก้อนที่ผู้ใช้ติ๊กแล้วถูกล็อกไม่ให้รอบถัดไปทับ
- Esc / ยกเลิก = ปิด Mirror · ไม่มีอะไรถูกเขียน · กระจกเก็บไว้ 7 วันใน `ziz.db` (เปิดต่อได้จาก Home)

### 3.3 ตัวแสดงผลต่อแอป (renderer)

Mirror ใช้ข้อมูลจาก `eco_get` + `eco_describe` ของแอป · หนึ่ง renderer ต่อ "รูปทรงข้อมูล" ไม่ใช่ต่อแอป (ponytail: 4 renderer ครอบ 7 แอป):

| renderer | รูปทรง | แอป | หน่วยของก้อน |
|---|---|---|---|
| **prose** | ข้อความยาว | RyuLong (บท/ฉาก) · DraconDex (Page block ข้อความ) · BahaMyth (คำอธิบายยาว) | ประโยค (ตัดด้วย `Intl.Segmenter('th', {granularity:'sentence'})` ของ JS) → ภายในก้อนไฮไลต์ระดับคำ (`granularity:'word'`) |
| **record** | entity มีฟิลด์ | BahaMyth (ตัวละคร/สถานที่) · QuetzaLib (หนังสือ) · Ourobask (งาน) · TiaMax (action) | ฟิลด์ (ชื่อ → ค่าเดิม → ค่าใหม่) · ลิงก์ = เพิ่ม/ลบความสัมพันธ์ |
| **table** | หลายแถว | QuetzaLib (รายการหนังสือ) · DraconDex (ตาราง) | แถว (+ ใหม่ / ✎ แก้ / − ลบ) · ภายในแถวไฮไลต์เซลล์ |
| **tree** | โครงสร้างซ้อน | LevelthanQ (เลเวล/เควสต์/เงื่อนไข) · RyuLong (book→chapter→scene) · BahaMyth (realm tree) | โหนด (ย้าย/เพิ่ม/ลบ/แก้) · ย้ายแสดงเป็นเส้นจากตำแหน่งเดิม |

แอปที่ประกาศ renderer ของตัวเองได้ในอนาคต (later) — v1 ใช้ 4 ตัวนี้

### 3.4 ไหลของข้อมูล

```
เปิด Mirror(target refs) → eco_get ทุก ref → snapshot ซ้าย (แช่แข็ง + version)
ผู้ใช้สั่ง → agent ได้ tool ใหม่ ziz_mirror_edit(mirrorId, ref, patch[]) (ผ่าน gateway · แก้ได้เฉพาะสำเนาใน Z.I.Z)
         → โมเดลเล็กช่วย: ner (ชื่อสะกดไม่ตรง) · index (หาที่อื่นที่ต้องแก้ตาม) · route (ตรวจ injection ในข้อความ)
         → diff(ซ้าย, ขวา) → ก้อน (hunk) พร้อม anchor + เหตุผล
ผู้ใช้เลือก → แปลงก้อนที่เลือกเป็น op ของ eco.changeset (`04` §3.4) → เส้นทางนำไปใช้เดิม
```
ตาราง `mirror(id, target_app, refs, base_versions, created_at)` · `mirror_rev(mirror_id, rev, prompt, agent, model_versions)` · `mirror_hunk(rev_id, n, ref, path, before, after, reason, evidence, state)`

- ทุกคำแนะนำบอก **ที่มา** (กฎของ Insight · index · ner · habit · agent) และมีปุ่มหลักปุ่มเดียว
- **ไม่มีการทำงานอัตโนมัติ** — ทุกการกระทำจากคำแนะนำไปทาง Mirror หรือแผงข้อเสนอเสมอ
- `ไม่ต้องแนะนำอีก` = ลดน้ำหนักรูปแบบนั้นถาวร (เก็บใน habit state)

### 4.2 ข้อมูลที่ใช้: `eco.activity` (ข้อเสนอ P12)

แอป Eco บันทึกการกระทำของผู้ใช้แบบ **ไม่มีเนื้อหา** (opt-in ต่อแอป ตั้งในแอปนั้น — แบบ ECO-S1):

```
<EcoProject>\.zydraxyl\activity\<app>.ndjson      (หมุนไฟล์ทุก 5 MB · เก็บ 90 วัน)
{"t":"2026-11-01T10:22:05Z","app":"baha","act":"entity.create","kind":"character","ref":"zydraxyl://baha/…/e/123","via":"user"}
{"t":"…","app":"baha","act":"asset.attach","kind":"character","ref":"…","via":"user"}
{"t":"…","app":"baha","act":"link.add","kind":"character→place","ref":"…","via":"user"}
```
- เก็บแค่ชนิดการกระทำ + kind + ref (ไม่มีชื่อ ไม่มีข้อความ) · `via` แยกการกระทำของผู้ใช้ออกจากของ Z.I.Z/agent (ไม่เรียนรู้จากตัวเอง)
- แอปยังไม่รองรับ → Z.I.Z ใช้การเขียนที่ผ่าน Z.I.Z เอง + diff ของ `eco_stats` ระหว่างครั้ง (หยาบกว่าแต่ใช้ได้)

### 4.3 ตรวจรูปแบบซ้ำ (`ZIZ-M-habit` — ไม่ใช่ neural)

1. แปลง event เป็น token `app:act:kind` · ตัดเป็น session (ห่างกัน > 10 นาที = session ใหม่)
2. นับลำดับย่อยต่อเนื่องยาว 2–6 ที่เกิด **≥ 3 ครั้ง ใน ≥ 2 session** (ทำทุกครั้งที่เปิด Spaces · ข้อมูล 90 วันเล็กพอจะนับตรง ๆ —
   ponytail: นับ n-gram ตรง ๆ O(N·6) · เปลี่ยนเป็น PrefixSpan เมื่อมีช่องว่างคั่นในลำดับแล้วจับไม่ได้)
3. คะแนน = ครั้ง × ความยาว × เวลาที่ใช้ต่อครั้ง (จาก timestamp) − โทษถ้าเคยกด "ไม่ต้องแนะนำอีก"
4. **ทำเป็น recipe** → สร้าง macro: ลำดับ op ที่มีพารามิเตอร์ (ค่าที่ต่างกันในแต่ละครั้ง = ช่องให้กรอก) → บันทึกเป็น `ziz.recipe` (`04` §3.3) ชนิด `macro` →
   รันแล้วผลไป **Mirror** ให้ตรวจก่อนเสมอ
5. "ถัดไปคุณมักจะ…" = Markov อันดับ 2 บน token ล่าสุด · แสดงเฉพาะความน่าจะเป็น ≥ 0.4 และเคยเกิด ≥ 5 ครั้ง
