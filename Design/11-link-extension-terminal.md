## 1. Z.I.Z Link คืออะไร

extension ตัวเล็กที่อยู่**ในหน้าต่างของแอป Eco** (DraconDex · BahaMyth · RyuLong · LevelthanQ · QuetzaLib · Ourobask · TiaMax) ทำ 3 อย่าง:

| # | งาน | ตัวอย่าง |
|---|---|---|
| L1 | **เชื่อมสิ่งที่อยู่บนจอ** — ส่ง "บริบทของมุมมองปัจจุบัน" (entity ที่เลือก · หน้าที่เปิด · ข้อความที่ highlight) ให้ Z.I.Z | เลือกตัวละคร "อาริน" ใน BahaMyth → แผง Link รู้ทันทีว่ากำลังพูดถึงใคร |
| L2 | **ถาม/ค้นข้อมูลของโปรเจกต์ แล้วสรุปแบบไว** | "อารินโผล่ในบทไหนบ้าง และสัมพันธ์กับใคร" → ได้สรุป 5 บรรทัด + ลิงก์ไปบท/entity ภายในไม่กี่ร้อยมิลลิวินาที |
| L3 | **เปิด Z.I.Z จากโปรเจกต์นี้ทันที** | ปุ่ม `เปิดใน Z.I.Z` → Z.I.Z เปิดโปรเจกต์เดียวกัน โฟกัสโหนดที่เลือกใน Home หรือเปิด Mirror กับ entity นั้น |

**ไม่ทำ:** เขียนข้อมูลลงแอป (การเขียนยังเกิดที่ปุ่มใน Z.I.Z / Mirror เท่านั้น — `05` หลักข้อ 2) · รัน CLI agent เองในแอป · เก็บความลับ

## 2. ติดตั้งอัตโนมัติเมื่อมีทั้งสองฝั่ง

### 2.1 เงื่อนไข

```
มี Z.I.Z ติดตั้งในเครื่อง   (locator: %LOCALAPPDATA%\Zydraxyl\locator\ziz.json — ต้องเพิ่ม ดู §2.4)
และ มีแอป Eco ที่รองรับ Link  (แอปประกาศ plugin host ใน eco.json: apps[].extensions.host = "zydraxyl-ext/1")
และ ผู้ใช้ไม่ได้ปิด "ติดตั้ง Link อัตโนมัติ" (ทั้งในแอปนั้นหรือใน Z.I.Z)
→ แอปฝั่งนั้นติดตั้ง ziz-link-<app> ให้เอง
```

### 2.2 ใครติดตั้ง — **แอปเจ้าบ้านเป็นคนติดตั้ง** (ไม่ใช่ Z.I.Z เขียนลงโฟลเดอร์ของแอปอื่น)

เหตุผล: โฟลเดอร์ plugin เป็นของแอปเจ้าบ้าน · สิทธิ์และการยินยอมตั้งในแอปเป้าหมาย (ECO-S1) · Z.I.Z ไม่ควรแตะไฟล์ของแอปอื่น (หลักการข้อ 3 ของสัญญา)

```
แอปเจ้าบ้านเปิด (หรือได้ยินว่า Z.I.Z เพิ่งถูกติดตั้ง — §2.3)
 → อ่าน locator ของ ziz → มี
 → อ่าน catalog.json ที่ลงลายเซ็น (catalog เดียวกับโมเดล `08` §6.3 · section "extensions")
 → เลือก ziz-link-<app> รุ่นสูงสุดที่ requires.host และ requires.ziz ตรงกับของในเครื่อง
 → ดาวน์โหลด · ตรวจ sha256 + ลายเซ็น · แตกลงโฟลเดอร์ plugin ของแอปเอง · โหลด
 → toast ครั้งแรกครั้งเดียว: "ติดตั้ง Z.I.Z Link แล้ว — ถามข้อมูลโปรเจกต์ได้จากแผงขวา · ปิดได้ในตั้งค่า → Extensions"
```
- ไม่มีเน็ต → ขอ pack จาก Z.I.Z ผ่าน pipe (`link_offer_pack` — Z.I.Z มี pack ที่เข้ากันได้ cache ไว้ใน `%LOCALAPPDATA%\ZIZ\extensions\`) · ยังตรวจลายเซ็นเหมือนเดิม
- แอปที่ยังไม่มี plugin host → ไม่ติดตั้ง · Z.I.Z แสดงในหน้า "การเชื่อมต่อ" ว่า "แอปนี้ยังไม่รองรับ Link" (ไม่ซ่อน)

### 2.3 ได้ยินว่าอีกฝั่งเพิ่งติดตั้ง

- แอปเจ้าบ้านตรวจ locator **ตอนเปิดแอป** เท่านั้น (ponytail: ไม่มี file watcher บนโฟลเดอร์ locator · ติดตั้ง Z.I.Z แล้วต้องเปิดแอปใหม่ ≤ 1 ครั้ง)
- ทางลัด: ตอน Z.I.Z ติดตั้งเสร็จ/เปิดครั้งแรก มันเรียก `--eco-open zydraxyl://<app>/ext/refresh` กับแอปที่**กำลังรันอยู่**ตาม `instances\*.json` (ECO-L5) → แอปตรวจ locator ใหม่ทันที
- **ถอนติดตั้ง Z.I.Z** → locator ของ ziz หาย → แอปปิดการทำงานของ Link (ไม่ลบไฟล์ทันที เผื่อติดตั้งกลับ) · ลบอัตโนมัติหลังหายเกิน 30 วัน

### 2.4 สิ่งที่เปลี่ยนจากเดิม

`06` §3.3 เดิมบอก "Z.I.Z ไม่เขียน locator ของตัวเองใน v1" → **เปลี่ยน:** Z.I.Z เขียน `locator\ziz.json` (ตาม ECO-L2 เหมือนแอปอื่น) เพื่อให้แอปเจ้าบ้านรู้ว่ามี Z.I.Z ·
ไฟล์มีแค่ path ของ exe · เวอร์ชัน · pipe ของ Link · protocol ที่รองรับ — ไม่มี workspace/ข้อมูลผู้ใช้

### 2.5 อัปเดต

- กลไกเดียวกับโมเดล (`08` §7.2): แอปเจ้าบ้านตรวจ catalog ≤ วันละครั้ง · ตรวจลายเซ็น/sha · เก็บรุ่นก่อนหน้า 1 รุ่น · ย้อนได้
- **Z.I.Z อัปเดตแล้ว protocol `link/N` เปลี่ยน MAJOR** → Link รุ่นเก่ายังคุยได้จนกว่าแอปจะดึงรุ่นใหม่ (Z.I.Z รองรับ `link/N` และ `link/N-1` ไปอีก 1 รุ่น MINOR)
- ค่าเริ่มต้น: **อัปเดตอัตโนมัติ** (ต่างจากโมเดลที่ "แจ้งก่อน") เพราะ Link ไม่เปลี่ยนผลของงาน และรุ่นเก่ามักคุยกับ Z.I.Z ใหม่ไม่ได้ — ❓ Q36

## 3. สถาปัตยกรรม

### 3.1 สองชั้น: UI กลาง 1 ชุด + adapter บาง ๆ ต่อแอป

```
ZIZ-LINK (repo ใหม่ — multi-repo แบบ `08` §5)
  ui/            web component <ziz-link-panel> (vanilla JS + tokens.css ของ Eco) — เหมือนกันทุกแอป
  adapters/
    dracon/      แปลง "สิ่งที่เลือก/หน้าที่เปิด" ของ DraconDex → LinkContext · ผูกเมนู/ปุ่มลัด
    baha/  ryu/  lvq/  qzl/  our/  tia/
  protocol/      link/1 schema (JSON Schema) + ชุดทดสอบด้วย Z.I.Z ปลอม
  release.yml    tag v* → สร้าง ziz-link-<app>-<ver>.zizext ต่อแอป → PR เข้า catalog (`08` §6.2)
```
`.zizext` = zip รูปแบบเดียวกับ `.zizpack` (`08` §6.1): `pack.json` (`kind: "extension"`, `host: "baha"`, `requires.host`, `requires.ziz`, `protocol: "link/1"`) + ไฟล์ UI + adapter

**แอปเจ้าบ้านต้องมี plugin host มาตรฐาน `zydraxyl-ext/1`** (ข้อเสนอ P14 · §6): ที่วางแผงขวา · การลงทะเบียนคำสั่ง/ปุ่มลัด · event "selection changed" · API อ่าน entity แบบอ่านอย่างเดียว ·
sandbox (iframe/`<webview>` ที่ไม่มี Node, CSP เข้ม) · storage ต่อ extension · DraconDex มี `PLUGINS.md` อยู่แล้ว → ใช้เป็นต้นแบบ ❓ Q35

### 3.2 การเชื่อมต่อ

```
[แอป Eco] ── sandbox ──> <ziz-link-panel>
                           │ host API: postMessage → main ของแอปเจ้าบ้าน
                           ▼
main ของแอปเจ้าบ้าน ──── \\.\pipe\zydraxyl-ziz-link-<SID> ────> Z.I.Z (core/link/server.js)
                           (ACL ผู้ใช้ปัจจุบัน + PIPE_REJECT_REMOTE_CLIENTS — เหมือน ECO-C5)
                                                                   ├ ziz-index (`09`) — ค้น
                                                                   ├ model-worker (`08`) — embed/ner
                                                                   └ CLI agent (`02` §3) — "ถามลึก" เท่านั้น
Z.I.Z ไม่รัน → ค้นอย่างเดียวต่อ ziz-index ตรง (pipe ของ `09` §5) · สรุป/เปิด Mirror → ปุ่ม "เปิด Z.I.Z"
```

- **การจับคู่ครั้งแรก (pairing):** Link ขอ token จาก Z.I.Z → Z.I.Z แสดง toast "BahaMyth ขอเชื่อมกับ Z.I.Z · [อนุญาต] [ปฏิเสธ]" ครั้งเดียวต่อแอป → token เก็บใน storage ของ extension (แอปเจ้าบ้านเข้ารหัสด้วย DPAPI)
- token ผูก **แอป + โปรเจกต์ที่แอปเปิดอยู่** — Link ถามได้เฉพาะโปรเจกต์ที่แอปนั้นเป็นสมาชิก (`members` ECO-L7)

### 3.3 protocol `link/1` (อ่านอย่างเดียวทั้งหมด)

| method | ทำอะไร | ช้า/เร็ว |
|---|---|---|
| `link_hello(app, appVersion, projectUid)` | ตรวจ protocol · คืนสิ่งที่ Z.I.Z ทำได้ตอนนี้ (มี agent? โมเดลไหนพร้อม?) | — |
| `link_context(ctx)` | ส่ง LinkContext ปัจจุบัน (§3.4) · Z.I.Z ใช้เป็นบริบทของคำถามถัดไปและโฟกัสโหนดใน Home ถ้าเปิดอยู่ | ทันที |
| `link_search(q, scope?)` | ค้น hybrid ใน `ziz-index` เฉพาะโปรเจกต์นี้ | < 50 ms |
| `link_brief(ctx \| q)` | **สรุปไว** (§4) — ไม่ใช้ CLI agent | < 500 ms |
| `link_ask(q, ctx)` → stream | **ถามลึก** — ส่งให้ CLI agent ของผู้ใช้ผ่าน Z.I.Z · แจ้งก่อนว่าใช้ agent (กินโควตา) | วินาที–นาที |
| `link_open(target)` | เปิด Z.I.Z: `home` (โฟกัส ref) · `mirror` (refs) · `spaces` (app) · `terminal` (§5) | ทันที |
| `link_offer_pack(app)` | ส่ง `.zizext` ที่ cache ไว้ (ทางออฟไลน์ §2.2) | — |

**ไม่มี:** method เขียน · method ที่รับ path ไฟล์ · การเปลี่ยนโปรเจกต์

### 3.4 LinkContext — "สิ่งที่อยู่บนจอ"

```json
{ "app": "baha", "projectUid": "…", "view": "entity",
  "selection": [ { "ref": "zydraxyl://baha/…/e/123", "kind": "character", "label": "อาริน" } ],
  "openRef": "zydraxyl://baha/…/e/123",
  "text": "ข้อความที่ผู้ใช้ highlight (≤ 2,000 ตัวอักษร)",
  "at": "2026-11-01T10:22:05Z" }
```
- ส่งเฉพาะเมื่อแผง Link เปิดอยู่ หรือผู้ใช้กดปุ่มลัด — **ไม่ส่งตลอดเวลา** · ไม่มีภาพหน้าจอใน v1 (ref + ข้อความพอ และไม่รั่วข้อมูลที่ไม่เกี่ยว) — ภาพหน้าจอ ❓ Q37
- adapter ต่อแอปรู้ว่า "สิ่งที่เลือก" ของแอปตัวเองคืออะไร: บท/ฉาก (RyuLong) · Page/block (DraconDex) · เควสต์ (LevelthanQ) · หนังสือ (QuetzaLib) · งาน (Ourobask)

## 4. "สรุปแบบไว" ทำอย่างไรโดยไม่ใช้ CLI agent

```
ctx/q → ziz-index: ค้น BM25 + ความหมาย ใน scope โปรเจกต์ (`09` §1)
      → เลือก ≤ 8 ข้อความที่ดีที่สุด (RRF) + entity ที่ ner พบร่วม + ลิงก์ข้ามแอปจาก cache ของ Insight
      → ประกอบเป็นสรุปแบบ "สกัด" (extractive): ข้อเท็จจริงสั้น ๆ ที่ยกจากข้อความจริงทุกบรรทัด + ตำแหน่งต้นทาง
      → [ถามลึกด้วย Claude Code →] ถ้าผู้ใช้ต้องการคำตอบที่เขียนใหม่/สังเคราะห์
```
ตัวอย่างผล (`link_brief` ของ "อาริน"):
```
อาริน · ตัวละคร · BahaMyth
• ปรากฏใน RyuLong 23 บท (บทที่ 1–9, 12, 15–27) · ครั้งแรก บทที่ 1 "อารินยืนอยู่ที่ท่าเรือ…"
• ถูกพูดถึงคู่กับ เซลีน 31 ครั้ง · ยังไม่มีความสัมพันธ์ใน BahaMyth  ✦ แนะนำ
• เควสต์ใน LevelthanQ ที่อ้างถึง: "ดาบจันทรา"
• สะกดเป็น "ริน" 9 ครั้ง (บท 3, 5, 8)                         [แก้ใน Mirror →]
ที่มา: index · ner 1.3 · 120 ms
```
- ทุกบรรทัดมีที่มา (หลักข้อ 3 "หลักฐานก่อนความเชื่อ") · ไม่มีประโยคที่โมเดลแต่งขึ้นเอง
- ถ้าภายหลังมี `ZIZ-M-gen` (`08` Q31) จะใช้เขียนสรุปเป็นย่อหน้าได้ — v1 เป็นแบบสกัดเท่านั้น

## 6. หน้าต่างแชต / Terminal ใน Z.I.Z

### 6.1 สองแท็บ หนึ่งหน้าต่าง

| แท็บ | คืออะไร | ใช้เมื่อ |
|---|---|---|
| **แชต** | Console เดิม (`05` §3.1) — คุยกับ CLI agent ผ่าน ACP · event มีโครงสร้าง · มีการ์ดงาน/ข้อเสนอ · สิทธิ์คุมโดย Z.I.Z (`02` §3.6) | งานปกติของ Z.I.Z |
| **Terminal** | terminal จริง (PTY) รัน shell ของผู้ใช้หรือ CLI แบบโต้ตอบ (`claude` · `codex` · `gemini`) **ใน cwd ที่ผู้ใช้เลือก** | login ครั้งแรก · ใช้ CLI เต็มความสามารถ · ผู้ใช้ที่ชอบพิมพ์คำสั่งเอง |

อยู่ใน dock ล่างของ Home (`10` §2) และ**แยกเป็นหน้าต่างลอย**ได้ (`Ctrl+\``) · หลายแท็บ terminal ได้

### 6.2 Terminal ทำงานอย่างไร

- **`node-pty`** (MIT, native — ใช้ ConPTY ของ Windows) + **xterm.js** (MIT) ใน renderer · PTY อยู่ใน main/utilityProcess · renderer ได้แค่ stream ผ่าน preload channel `ziz.term.*`
- shell เริ่มต้น: PowerShell (ตั้งค่าได้: pwsh · cmd · Git Bash · WSL)
- ปุ่มลัดเหนือ terminal: `▶ claude` `▶ codex` `▶ gemini` (เฉพาะที่ตรวจเจอ — `02` §3.3) · `เข้าสู่ระบบ` (รัน `claude` ครั้งแรกให้ login — แก้ error อันดับหนึ่งใน `05` §6)
- **โหมด "ต่อกับโปรเจกต์" (opt-in ต่อแท็บ):** เปิด CLI พร้อม MCP ของ Z.I.Z แบบอ่านอย่างเดียว:
  `claude --mcp-config <tmp>/ziz-readonly.json` → agent ในterminalค้นโปรเจกต์ได้ผ่าน `ziz_index_search`/`ziz_app_get` แต่**ไม่มี tool เขียน** ·
  เป็นทางเดียวกับ F8/Q15 แต่จำกัดอยู่ในแท็บนี้และใช้ gateway ของ Z.I.Z (ไม่ใช่ MCP ของแอปตรง ๆ)
- **ห้ามเติม flag อันตราย** (`--dangerously-*`, `--yolo`) ในปุ่มลัดใด ๆ — ผู้ใช้พิมพ์เองได้ แต่ Z.I.Z ไม่ทำให้

### 6.3 ขอบเขตความปลอดภัย (Terminal ≠ agent ของ Z.I.Z)

| | แชต (ACP) | Terminal |
|---|---|---|
| ใครสั่ง | ผู้ใช้ผ่าน Z.I.Z → agent | **ผู้ใช้พิมพ์เอง** |
| shell/ไฟล์ | agent ถูกปฏิเสธอัตโนมัติ · cwd = scratch | เต็มสิทธิ์ของผู้ใช้ (เหมือนเปิด Windows Terminal) |
| Z.I.Z ส่งข้อความเข้า terminal | ไม่มี | **เฉพาะเมื่อผู้ใช้กด** "ส่งไป terminal" (เช่นคำสั่งที่ Z.I.Z แนะนำ) — แสดงคำสั่งให้เห็นก่อนกด Enter เสมอ |
| Z.I.Z อ่านผลจาก terminal | — | ไม่อ่าน/ไม่บันทึกโดยค่าเริ่ม (ไม่ใช่ audit log) · ผู้ใช้เลือกข้อความแล้ว "ส่งไปแชต" ได้ |
| เนื้อหาไฟล์ของผู้ใช้ | ผ่าน gateway เท่านั้น | — |

เหตุผลที่แยกชัด: การป้องกัน prompt injection ของ Z.I.Z (`04` §7) พึ่งการที่ agent ในแชตไม่มี shell — Terminal จึงต้องเป็นของผู้ใช้ล้วน ไม่ใช่ทางลัดให้ agent
